# CodeDD SEO and LLM discoverability

Every public page must ship **both**:

1. **Optimal metadata** — Next.js `Metadata` via `createPageMetadata`
2. **Machine-readable content** — visible HTML + `PageJsonLd` + listing in `sitemap.xml` and `llms.txt`

Do not invent a second metadata helper or raw `<meta>` / JSON-LD tags.

## Reuse these files

| Piece | Path |
|-------|------|
| Metadata + JSON-LD builders | `src/lib/seo.ts` |
| Site origin / port | `src/lib/site.ts` (`SITE_ORIGIN`, port **3005**) |

| Docs corpus | `content/documentation/*.md` via `src/lib/docs.ts` |

## New page checklist

Copy this and complete it:

```
- [ ] createPageMetadata({ title, description, path })
- [ ] PageJsonLd or MarketingStub path={...}
- [ ] One visible <h1> that matches the topic of title
- [ ] Visible <p> lead that matches description (not image-only text)
- [ ] Semantic HTML: article/section, h2+ for subsections
- [ ] Descriptive <Link> text (not “click here”)
- [ ] Path listed in getIndexablePaths() if it is not already in nav.ts
- [ ] html lang stays "en" (root layout)
```

### 1. Metadata (required)

```ts
import { createPageMetadata } from "@/lib/seo";

export const metadata = createPageMetadata({
  title: "Architecture",
  description: "Structure, coupling, and scalability from a CodeDD audit.",
  path: "/products/architecture",
});
```

`createPageMetadata` already sets canonical, Open Graph, Twitter, and robots. Do not re-declare those unless you are changing them on purpose (`index: false` for thank-you / internal pages).

| Field | Rules |
|-------|--------|
| `title` | Unique, ~50–60 chars. Layout appends ` \| CodeDD`. Home uses the absolute site title. |
| `description` | Unique, ~140–160 chars. What the page is, who it is for, no keyword stuffing. |
| `path` | Real route, starts with `/`. Used for canonical + OG URL. |
| `ogType` | `"article"` for docs / long-form. Default `"website"`. |

Dynamic routes: use `generateMetadata` and call the same helper with the resolved path.

### 2. Machine-readable body (required)

**Humans and LLMs must be able to read the same words in the HTML.** Do not put the only explanation in a screenshot, canvas, or client-only fetch.

```tsx
<MarketingStub
  path="/products/architecture"
  eyebrow="Benchmarking"
  title="Architecture"
  description="Structure, coupling, and scalability from a CodeDD audit."
/>
```

`MarketingStub` emits `PageJsonLd` when `path` is set.

Pages that do not use `MarketingStub` must render:

```tsx
<PageJsonLd title={...} description={...} path={...} breadcrumbs={[...]} />
```

Inside `<main>` (already in the root layout):

- Exactly one `<h1>`
- Lead paragraph in real text
- Headings in order (`h2` then `h3`)
- Lists for enumerations (products, steps, FAQs)
- FAQ blocks use `<h2>` questions + `<p>` answers, and `type="FAQPage"` on `PageJsonLd` when the page is primarily FAQ

### 3. Register the URL

If the route is **not** already a link in `src/lib/nav.ts`, add it to `getIndexablePaths()` in `src/lib/seo.ts`. Sitemap and `llms.txt` consume that list (docs slugs are appended separately).

## Favicon and social image

Reuse the tokens — do not add another PNG/SVG pair:

- Favicon / apple icon: `/codedd.svg` via `SITE_ICONS`
- Every Open Graph + Twitter card: `/og-image.png` via `OG_IMAGE` (1200×630)

`createPageMetadata` and the root layout already attach both. Only override `images` if a page has a unique share card.

## Documentation markdown (`content/documentation/`)

The markdown is owned by **codedd_app** (`src/landingpage/documentation/doc-readmes/*.md` + `doc-registry.json`); the Django AI advisor indexes the same files. `content/documentation/` is generated by `npm run docs:sync` and gitignored. Edit guides in codedd_app, never here.

Do **not** rewrite guide bodies. SEO is applied in the loader and routes:

- Frontmatter `title` + `description` are the source of truth
- `src/lib/docs.ts` builds a ~160-char `description` (frontmatter, then first prose paragraph — never the first `##` heading)
- Each guide is a `TechArticle` (or `FAQPage` when 3+ `## …?` headings exist)
- File mtime becomes `dateModified` / sitemap `lastModified`
- HTML: `/documentation/{slug}` — listed in `sitemap.xml` and `/llms.txt`
- Verbatim markdown: `/documentation/{slug}/raw` — `text/markdown` alternate for agents
- Whole corpus in one file: `/llms-full.txt`
- The page renders the frontmatter title as the only `<h1>` and strips the body's leading `# Title`

New `.md` files need YAML frontmatter:

```yaml
---
title: Short unique title
description: One sentence, ideally 110–160 characters, of what the guide covers.
category: Software Audit
order: 1
---
```

Then add the file id to `doc-registry.json` in codedd_app (category, order, icon). The registry wins over frontmatter `category`/`order`; keep them equal. Slug is generated from the title. The sitemap and `llms.txt` pick the page up automatically.

`npm run docs:check` (also `prebuild`) fails on a doc without a registry entry, duplicate slugs, frontmatter/registry drift, a `/documentation/<slug>` or `#anchor` link that does not resolve, and a `/documentation#category` anchor in `nav.ts` that no longer matches a category.

## Site-wide surfaces (do not duplicate)

- `/robots.txt` — allow all crawlers, including LLM bots, unless legal says otherwise
- `/sitemap.xml` — every public URL
- `/llms.txt` — short, factual index for agents ([llmstxt.org](https://llmstxt.org/)). Its "Key facts" block and Company links are hand-written: list only real pages, never `MarketingStub` placeholders.
- Sitelinks — `siteNavigation` in `src/lib/nav.ts` feeds the root `SiteNavigationElement` list. Google picks sitelinks itself; give every target page a distinct title and meta description, and keep it linked from the header.

When adding a major section, add a heading + markdown links in `src/app/llms.txt/route.ts` if it will not appear via nav/docs generation.

Production: set `NEXT_PUBLIC_SITE_URL` to the public origin (`https://codedd.ai`). Local origin is `http://localhost:3005`.

## Positioning (copy)

From `docs/POSITIONING.md`: CodeDD is **codebase risk intelligence**, not “end-to-end software intelligence” and not a developer-activity dashboard. Do not use “end-to-end” in titles or descriptions.

## Anti-patterns

- Page with only `title:` and no `createPageMetadata` / no JSON-LD
- Duplicate `<title>` via a manual `<head>`
- Text baked into images or `GenerateImage` as the only content
- `noindex` on a marketing page by default
- Keyword lists instead of a sentence description
- A second `sitemap.ts` or `robots.ts`
